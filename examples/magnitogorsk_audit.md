## Найденные расхождения

1. density.csv содержит нули для неопределённых отношений у незастроенных кварталов.
   Это старый кэш, а не поведение исправленного раздела 10. При обновлении из готовых
   buildings_blocks используются исходные формулы библиотеки, сохраняя NaN/Infinity.
2. В _supply_self BlocksNet 1.0.0a9 локальная ёмкость вычитается из capacity_left,
   но не добавляется к capacity_within. reconcile_self_supply восстанавливает этот
   бухгалтерский баланс лишь если разница точно объясняется min(demand, capacity).
   Спрос, маршруты, links, выбранные школы и обеспеченность не пересчитываются.
3. assign_land_use суммирует пересечения перекрывающихся полигонов. Поэтому сохранённые
   share и коэффициенты типов использования местами больше 1. Значения не обрезаются:
   подписи дашборда исправлены на «сумма пересечений», добавлено пояснение.
4. Отрицательный OSR означает, что агрегированная площадь застройки больше площади
   квартала. Нужна содержательная проверка пограничных зданий; произвольной замены нет.
5. Старый run_meta не доказывает версию и историю расчёта. Даже после обновления паспорта
   история старой матрицы (были ли Infinity заменены конечным временем) не восстанавливается.
6. Добавлены отсутствовавшие saved summary, центры кластеров, links, сырые агрегаты и
   отдельный graph_meta. Матрица опциональна из-за размера; другие показатели доступны без неё.

## Однократное обновление производных результатов

В ядре .venv Python 3.12:

1. После перезапуска выполните целиком 8-ю кодовую ячейку ноутбука — первую кодовую
   ячейку раздела 5 с заголовком `5.0. ВОССТАНОВЛЕНИЕ СОСТОЯНИЯ`. Она сама восстанавливает импорты, пути, параметры,
   функции, кварталы и границу; разделы 1–4 выполнять не нужно.
   Следующую, 9-ю кодовую ячейку построения графа, не выполняйте.
2. В отдельной ячейке: REFRESH_SAVED_DERIVED = True.
3. Выполните 13-ю кодовую ячейку — раздел 9: чтение готового provision и исправление учёта self_supply.
4. Выполните 14-ю кодовую ячейку — раздел 10: арифметические формулы по buildings_blocks.geojson без загрузки зданий.
5. Выполните 18-ю кодовую ячейку — раздел 14: сборка и сохранение итогового слоя, таблицы, сводки и паспорта.
6. В отдельной ячейке: REFRESH_SAVED_DERIVED = False.

До замены старые производные файлы копируются в examples/data_magnitogorsk/backups/.
Ничего не удаляйте. Разделы 1–8, 11–13 не нужно повторять; граф, матрица и геоданные
не пересчитываются. Классификации основаны на застроенных кварталах, чьи входные значения
плотности при этой корректировке не меняются.

## Обычное чтение готовых результатов

После обновления, для просмотра в ноутбуке выполните ячейку `5.0. ВОССТАНОВЛЕНИЕ СОСТОЯНИЯ`
с REFRESH_SAVED_DERIVED=False, затем необходимые разделы 9–14. Они читают свои результаты
из кэша. Не используйте Restart & Run All для короткого просмотра.
Для построения HTML запускать ноутбук вообще не требуется.

Из корня проекта, PowerShell:

```powershell
.\.venv\Scripts\python.exe .\examples\build_magnitogorsk_dashboard.py
```

Или один HTML со всеми сохранёнными временами между кварталами:

```powershell
.\.venv\Scripts\python.exe .\examples\build_magnitogorsk_dashboard.py --include-matrix
```

Откройте dashboard.html в корне проекта. Включение матрицы заметно увеличивает HTML
и потребление памяти браузером. Сборка только читает готовые файлы, не обращается к сети
и не запускает BlocksNet. Повторная команда обновляет HTML, не исходные результаты.
